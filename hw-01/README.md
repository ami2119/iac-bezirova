# hw-01 — стенд для показа продукта клиентам

Домашняя работа №1, вариант 4.
Стенд поднимается одной командой, переживает отказ одной машины,
между показами не работает (поднимается перед показом (create.sh) и сносится после (destroy.sh); постоянно в облаке не остаётся ничего — все ресурсы удаляются вместе со стендом.)

## Состав стенда

- **Сеть** `bezirova-04-net`, две подсети:
  - `bezirova-04-subnet-a` (зона `ru-central1-a`, `10.14.1.0/24`)
  - `bezirova-04-subnet-b` (зона `ru-central1-b`, `10.14.2.0/24`)
- **NAT-шлюз** `bezirova-04-nat` + таблица маршрутизации `bezirova-04-rt`,
  таблица маршрутизации привязана к подсети A: она даёт серверу приложения выход в интернет
  (для установки nginx через cloud-init), не открывая его снаружи.
- **Веб-серверы** (3 шт., распределены по двум зонам, с публичными адресами):
  `bezirova-04-web-1` (A), `bezirova-04-web-2` (B), `bezirova-04-web-3` (A).
- **Сервер приложения** `bezirova-04-app-1` (зона A, **без публичного адреса**),
  с дополнительным диском `bezirova-04-data` (20 ГБ).
- **Балансировщик** `bezirova-04-lb`: принимает снаружи на 80,
  раздаёт на порт 8012, проверка состояния по HTTP GET `/`.
- **Целевая группа** `bezirova-04-tg`: только веб-серверы.

## Как поднять

Из корня репозитория:

    bash hw-01/create.sh

Параметры можно передать аргументами:

    bash hw-01/create.sh <число_веб-серверов> <размер_диска_ГБ>

Повторный запуск безопасен: скрипт проверяет, что ресурс уже есть,
и пропускает его создание.

## Как проверить

    bash hw-01/check.sh ; echo "exit=$?"

Проверки представляют собой:
1. Балансировщик отвечает HTTP 200.
2. Отвечает больше одной машины.
3. Сервер приложения доступен с `bezirova-04-web-1` по внутреннему адресу.

Код возврата `0` — всё в норме, `1` — хотя бы одна проверка не прошла.

### Что делать, если check.sh вернул 1

- **Проверка 1 FAIL** — балансировщик не отвечает. Посмотреть
  `yc load-balancer network-load-balancer list` и `yc load-balancer network-load-balancer target-states ...` —
  есть ли хоть одна HEALTHY машина. Если все UNHEALTHY —  зайти на любую машину и проверить `sudo nginx -t` и
  `grep listen /etc/nginx/sites-available/default`.
- **Проверка 2 FAIL** — отвечает одна машина. Посмотреть
  `target-states`: скорее всего, часть машин UNHEALTHY. Причина обычно в nginx на конкретной машине, а не в балансировщике.
- **Проверка 3 FAIL** — app-машина недоступна с web-1.
  Проверить, что машина RUNNING, что на ней отвечает nginx на 8012, и что подсеть A привязана к таблице маршрутизации
  `bezirova-04-rt` (иначе cloud-init не поставит nginx).

## Как снести

    bash hw-01/destroy.sh

Скрипт находит ресурсы по префиксу `bezirova-04-` и удаляет
в обратном порядке создания. Устойчив к частично удалённому стенду — можно запускать повторно.
